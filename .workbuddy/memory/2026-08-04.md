# 2026-08-04

## 修复子目录项目（xcsc-site）部署失败
- 实际部署平台是 **Vercel**（非 Cloudflare）。首次日志误判为 Cloudflare，本质问题相同：平台在仓库根目录执行 `npm run build`，但 `package.json` 在 `xcsc-site/` 子目录，导致 ENOENT。
- 解决：仓库根目录新建 `package.json`，build 脚本为 `cd xcsc-site && npm install && npm run build && rm -rf "$(cd .. && pwd)/dist" && cp -r dist "$(cd .. && pwd)"`，把子项目产物复制到根目录 `dist`。
- 新建根目录 `.gitignore`（忽略 node_modules/dist/log）。
- 已本地提交（commit e32d845），由用户自行 `git push origin main`。
- Vercel 设置：Build command = `npm run build`（已生效）；Output Directory = `dist`（根目录产物）。若 Vercel 未自动识别框架，需手动把 Output Directory 设为 `dist`。

## GitHub Pages 也试了 → 404
- 原因：GitHub Pages 是纯静态托管，不会执行 `npm run build`。仓库根目录（Pages 默认指向处）没有 `index.html`，访问返回 404。
- 注意：`xcsc-site/vite.config.js` 的 `base: './'`（相对路径），已兼容 GitHub Pages 子路径，无需改。
- 解决：新增 `.github/workflows/deploy.yml`，用 GitHub Actions 在 CI 中 `cd xcsc-site && npm install && npm run build`，上传 `xcsc-site/dist` 并部署到 Pages。
- 用户需自行：commit+push 后，到仓库 Settings → Pages → Source 改为 "GitHub Actions"，首次 push 后 Actions 自动跑部署。
